% ------------------------------ QUESTION / APPROACH / PROOF ------------------------------
\begin{minipage}[t]{0.605\textwidth}
\sect{The question}
How can a bank turn \textbf{raw card transactions} into a \textbf{personal, compliant message} about a benefit that is worth real euros to that customer, at scale, and without wasting contacts?

\vspace{4pt}
\sect{PoC approach: five questions, answered in order}
\begin{enumerate}[label=\textbf{\arabic*.},leftmargin=11pt]
\item \textbf{Understand the spend.} Categorise every transaction into 14 sectors: text classifiers (several trained and compared) plus a deterministic MCC dictionary.
\item \textbf{Understand the customer.} One row per customer (monthly RFM, category shares, credit health), then PCA + K-Means into 3 segments.
\item \textbf{Decide whether and what.} An uplift model (X-Learner) removes customers an offer would hurt; own-spend valuation gives \eur/month net of fee; a Thompson-Sampling bandit selects \emph{one} offer.
\item \textbf{Personalise.} A persona (channel, tone, motivation, language) shapes the wording.
\item \textbf{Write and control.} An LLM agent drafts; rule checks and an LLM judge must pass, else retry twice, else flag for a human.
\end{enumerate}
\end{minipage}\hfill

\begin{minipage}[t]{0.55\textwidth}
\sect{Why this design}
\begin{itemize}
\item \textbf{A tree of decisions, not one model.} Each stage has one job and one output, and can be audited or swapped (e.g.\ own classifier $\to$ vendor API) without touching the rest.
\item \textbf{Value before wording.} The \eur\ figure comes from the customer's own spend; the LLM may only quote numbers from the fact sheet.
\item \textbf{Guard-rails at both ends.} The uplift gate removes customers an offer would hurt; the QA gate removes messages that break rules (currency, invented numbers, tone, over-promising).
\item \textbf{Swappable simulators.} Campaign, persona and acceptance are stand-ins; the interfaces take real logs unchanged.
\end{itemize}
\end{minipage}

% ------------------------------ FURTHER IMPROVEMENTS ------------------------------
{\color{navy}\bfseries\small Further improvements}\hfill{\tiny\color{cg}numbered badges on the pipeline show where each one plugs in}\par\vspace{-3pt}{\color{navy}\rule{\linewidth}{0.6pt}}\par\vspace{5pt}
\begin{minipage}[t]{0.325\textwidth}
\begin{imp}{(1)}{Visual content}
\textbf{Include images in e-mails} (and in-app): a visual per benefit and persona (hotel, dining, travel\dots) from a vetted, brand-safe library or a generative model, selected by the same persona and offer signals.\\[2pt]
\textit{Measure:} open and click uplift against text-only (A/B).
\end{imp}
\end{minipage}\hfill
\begin{minipage}[t]{0.325\textwidth}
\begin{imp}{(2)}{Aspirations, not only value}
\textbf{Add data sources} (e.g.\ web scraping of public signals) to read \emph{aspirations} on top of euro value. Example: a customer shows an interest in massage $\to$ recommend a \textbf{well-being offer to premium members}.\\[2pt]
\textit{Guard-rail:} consent and GDPR review before any enrichment.
\end{imp}
\end{minipage}\hfill
\begin{minipage}[t]{0.325\textwidth}
\begin{imp}{(3)}{Tone from real interactions}
\textbf{Deduce tone from e-mails}: an agent analyses client--bank exchanges and replaces the synthetic persona. \textbf{Only for curated clients}, those whose spend justifies a new card, so analysis cost is not wasted.\\[2pt]
\textit{Output:} tone, register and language per client.
\end{imp}
\end{minipage}
